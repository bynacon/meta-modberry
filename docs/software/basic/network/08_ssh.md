# SSH Access (OpenSSH, Bynacon service key)

| Field | Value |
| :-- | :-- |

---

## 1. Purpose

This module provides an encrypted shell with OpenSSH. Login is possible only with SSH keys: the Bynacon service key, which is part of the image, and further keys from provisioning. Root login is not possible.

---

## 2. Scope

### In scope

- OpenSSH server configuration.
- Bynacon service key and further authorized keys.
- Host keys.

### Out of scope

- Accounts and `sudo` → `BASE-INIT`
- Firewall openings and `service_nets` → `BASE-FWP`
- Brute-force protection → `BASE-IDS`

---

## 3. Components

| Package | Source layer | Replaces / removes |
| :-- | :-- | :-- |
| `openssh-sshd`, `openssh-ssh`, `openssh-keygen` | `poky` (openembedded-core) | `dropbear` (`ssh-server-dropbear`) |
| `modberry-service-key` (new: Bynacon service public key) | `meta-modberry` | — |

---

## 4. Requirements

- `BASE-SSH-01` **MUST** OpenSSH is the only SSH server. `dropbear` is not part of the image.
- `BASE-SSH-02` **MUST** Authentication is key-based only: `PasswordAuthentication no`, `KbdInteractiveAuthentication no`.
- `BASE-SSH-03` **MUST** Login as root is not possible (`PermitRootLogin no`).
- `BASE-SSH-04` **MUST** SSH host keys are generated on the device at first boot and stored persistently. They are not part of the image.
- `BASE-SSH-05` **MUST** The image contains exactly one authorized key: the Bynacon service public key for `user`. Further keys are added by provisioning (`BASE-PROV`).
- `BASE-SSH-06` **MUST** The Bynacon service key can be replaced by an image update, without reprovisioning the device.
- `BASE-SSH-07` **MUST** If `/data` is not available (e.g. locked, `BASE-LUKS-12`), sshd starts with temporary host keys generated in `/run`, so that login with the service key remains possible.

---

## 5. Configuration

| Target path | Key settings | Req. |
| :-- | :-- | :-- |
| `/etc/ssh/sshd_config` (layer file) | `PasswordAuthentication no`, `KbdInteractiveAuthentication no`, `PermitRootLogin no` | `BASE-SSH-02`, `BASE-SSH-03` |
| `/etc/ssh/sshd_config` | `AuthorizedKeysFile .ssh/authorized_keys /data/provisioning/ssh/authorized_keys` | `BASE-SSH-05` |
| `/home/user/.ssh/authorized_keys` | Bynacon service public key, mode `0600` | `BASE-SSH-05`, `BASE-SSH-06` |
| `/etc/ssh/ssh_host_*_key` | generated by `sshdgenkeys.service`, persistent (`/etc` overlay on `/data`) | `BASE-SSH-04` |
| `sshdgenkeys.service.d/` | fallback: keys in `/run/ssh/` if `/data` is not mounted | `BASE-SSH-07` |

---

## 6. Interfaces to Other Modules

### Provides

- SSH on 22/tcp – opened by `BASE-FWP`.
- SSH access with the Bynacon service key – used by `BASE-PROV` (factory provisioning).
- sshd authentication log – used by `BASE-IDS` (Fail2Ban).

### Consumes

- Account `user` – owned by `BASE-INIT`.
- Further authorized keys – owned by `BASE-PROV`.
- Persistent `/etc` overlay – owned by `BASE-ROOTFS`.

## 8. Constraints & Risks

- `BASE-SSH-01`: the current image uses `dropbear` (`ssh-server-dropbear` in `local_kirkstone.conf`). `openssh_%.bbappend` adds `file://sshd_config`, which does not exist in the layer, so the poky default is used.
- `BASE-SSH-02`: **human gate** – password login is disabled only after login with the service key has been verified on the device.
- `BASE-SSH-02`: `recipes-connectivity/openssh/files/ssh_config` is an unused client configuration with invalid options (`AllowRootLogin Yes`); it is removed.
- `BASE-SSH-05`: **one service key for all devices** – if its private part is compromised, every device is affected. Keep it on a hardware token; `BASE-SSH-06` allows rotation. SSH is reachable only from `service_nets`, the VPN and the USB service port.
